# Testing

The tests are deterministic. They use fixed inputs and exact counts. They do not use random numbers, sockets, databases, wall-clock delays as inputs, or a GUI window. One quality test checks that a 60 second virtual delay returns in well under five seconds of real time.

## Layout

`tests/test_harness.hpp` defines `INCIDENTLAB_TEST` and `EXPECT`. Each source file sets `INCIDENTLAB_TEST_SUITE` before including the harness. `incidentlab_tests` prints one line per case. A failure includes the condition text and the source line. The process exits non-zero if any case fails.

CTest does not know the 245 names by itself. It runs eight commands:

| CTest name | File | Cases |
| --- | --- | ---: |
| `incidentlab_domain` | `tests/domain_tests.cpp` | 21 |
| `incidentlab_simulation` | `tests/simulation_tests.cpp` | 37 |
| `incidentlab_failure` | `tests/failure_tests.cpp` | 30 |
| `incidentlab_resilience` | `tests/resilience_tests.cpp` | 29 |
| `incidentlab_observability` | `tests/observability_tests.cpp` | 52 |
| `incidentlab_visualization` | `tests/visualization_tests.cpp` | 30 |
| `incidentlab_scenario` | `tests/scenario_comparison_tests.cpp` | 30 |
| `incidentlab_quality` | `tests/quality_tests.cpp` | 16 |

Domain tests call services and `EventHistory` directly. The simulation, failure, resilience, observability, visualization, and scenario suites run the engine, the controller, or the comparison. Those are the integration tests. The visualization suite uses `SimulationController` and does not open raylib. The quality suite covers boundaries that the earlier files left implicit: the maximum clock value, a scheduler event added after a pop, replacement of a failure policy, the completed-request partition, dead-letter identity across two engines, the circuit reset boundary, retry backoff limits, and copies that outlive the engine.

`cached()` in the scenario file is a function-local static report. Tests read it. They do not share a mutable engine.

## Commands

```bash
cmake --preset debug
cmake --build --preset debug
ctest --test-dir build/debug --output-on-failure

cmake --preset release
cmake --build --preset release
ctest --test-dir build/release --output-on-failure
```

Sanitizer and coverage commands are in [build-guide.md](build-guide.md).

## Limitations

- A high coverage percentage does not prove the remaining lines are correct, or that the excluded GUI draws the right pixels.
- Headless controller tests do not check font sharpness, overlap, or click targets. Those were checked manually for the screenshots in `docs/screenshots/`.
- AddressSanitizer and UndefinedBehaviorSanitizer detect specific runtime faults. A clean run does not prove every lifetime is safe.
- Ordinary assertions do not prove the absence of every dangling reference. The quality tests copy reports out of the objects that produced them, and the sanitizer build ran those tests.
- CI results describe the commit that was checked out. A later unpushed change is not covered by the green run.
